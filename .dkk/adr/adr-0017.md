# ADR-0017 — Video prompt discipline, seeds and a pinned video model

## Context

Shots drift: a character's face changes between shots, two copies of one person appear, the location's light jumps, and a retake of a good shot cannot be reproduced. The consistency research (`docs/research/video-consistency-tactics.md`) weighed the evidence; this decision covers its items 2 and 3 (plan `docs/plans/06-consistency.md`), the ones that need no new generation step. The official Seedance 2.0 prompt guide reports that precise per-second timing "is unstable", that stability drops past four people and that four or five reference assets work best, that each reference should be named on every mention, and that subtitles and faces need saying. Wan's `prompt_extend` and similar rewriters change a prompt the studio composed on purpose. A retake needs the seed and the model version the first take used, and the episode's model could change under it whenever the service's model list was reordered, because "the model" was always the service's first.

## Decision

- **The API frames every video prompt** in `RequestShotVideo`, whatever wrote the body: the drama's style; a legend of the slots (`Characters: Mei (@Image1). Location: Night market (@Image2). Props: …`, left out for a provider that names references plainly); the body with each timed line (`0-3s:`) rewritten to `Shot N:`; the bound scene's lighting verbatim (`Lighting: …`); an identity sentence when a character is pictured, a no-subtitles sentence always, and `All dialogue is spoken in <language>.` when the body holds dialogue (`{…}` or quotes), in the app's content language. The prompt generator writes untimed `Shot N:` lines, a mention on every appearance, one slow camera move per line and dialogue in braces after the speaker; the storyboard breaker gives each sub-shot one camera move and each shot at most four characters (template v8).
- **Reference slots are capped per call and ordered by kind**: bound characters (at most four), then the scene, then props, at most five bound assets in all and never more than the model's image limit (less any reference videos and audio it counts), the assets the prompt mentions chosen before the rest; then the shot's uploaded and the request's extra images in whatever room the model's limit leaves. Slots are deduplicated by image path. A character now precedes the scene (the earlier order put the scene first) so identity references take the first slots, and a character beats a same-named scene. Everything left out is reported as `droppedReferences`, recorded on the task and shown per version.
- **Seed per take.** A model that takes a seed (caps flag `seed`: Ark Seedance, Wan, the stub, a ModelRunner endpoint whose schema has an integer `seed` on every mode it uses) gets the request's seed or one drawn in `[0, 2^31-1]`; the task records it and the shot's history shows it with the model, with a retake on the same seed. The retake is offered only while that version's model is the episode's current target, since a seed means nothing to another model, and it reuses the seed with the shot's current prompt and references. A seed sent for a model that takes none is refused. Seeds are a retake tool, not a continuity lever.
- **One fixed negative prompt** (duplicate person, identity change, distorted face or hands, subtitles, watermark, flicker…) goes to every model that takes one: Wan's `negative_prompt` (500 characters) and a ModelRunner endpoint's `negative_prompt`. It is a constant, not a capability or a setting.
- **Prompt rewriting is off.** Wan sends `prompt_extend: false`; a ModelRunner endpoint's boolean `enable_prompt_expansion`, `prompt_extend`, `prompt_optimizer`, `enhance_prompt` or `expand_prompt` is sent `false`.
- **The episode pins its video model** (`episodes.video_model`, migration 0007). The first generation that resolves the episode's locked service without an explicit model claims the pin in the same transaction that reads it: the stored model while the service still lists it, else the service's first, written back. Later generations, the episode view's `defaultModel` and the agents' model description use the pin; an explicit pick in the top bar overrides it for that call and leaves it alone. Offline (stub) mode writes nothing, as with the lock. Migration 0007 backfills an episode that already has videos with the model of its first completed video on its locked service.
- **The workspace template upgrades unedited files** (amends `adr-0006`'s copy-once rule). `workspace/.template-history.json` holds the sha-256 of every version each template file has had (`scripts/template-history.mjs`, checked by `pnpm lint`). At boot a missing file is copied, a file whose hash is a past template version is replaced by the current one, and any other file is the creator's edit: kept and reported. A file the creator replaced with a symbolic link is kept too, so an upgrade never writes through a link. So prompt and skill fixes reach existing installs without overwriting a creator's work.

## Alternatives Considered

- **Leave the prompt as the agent wrote it.** Rejected: framing in the API holds for prompts written by hand, by older templates and by the assistant, and keeps the lighting, identity and language sentences out of every skill.
- **Per-character caps from the provider table.** Rejected for now: the guide's limits are about output stability, not the API's acceptance, and they are the same for every model we drive.
- **A negative-prompt capability flag or a setting.** Rejected: the text is fixed, the adapters already know whether the endpoint takes it.
- **Seed on by default as a continuity tool.** Rejected: the same seed with a different prompt or references gives an unrelated clip.
- **Pin a model version string inside the service row.** Rejected: a service is shared by episodes; the pin is per episode, like the lock.
- **Overwrite the whole workspace on a version bump.** Rejected: it destroys creators' prompt edits. **Keep copy-once.** Rejected: fixes like this one would never reach an existing install.

## Consequences

- Contracts: `VideoProviderCaps.seed`, `RequestShotVideo.seed`, `ShotVideo.seed` and `ShotVideo.droppedReferences`, `Episode.videoModel`. Adapters gain a seed and a negative prompt on the record; the ModelRunner adapter reads three more roles from endpoint schemas.
- Migration 0007 adds `episodes.video_model`; workspace template v8; `pnpm lint` fails when a template file changed without its history entry.
- Shots with more than four characters or more than five bound assets now send fewer references; the studio greys out what a version left out, and the request warns.
- Item 1 (headshot and body references), the first and last frame roles (items 6 and 7), voice pinning and post-production conform stay open in plan 06.

## Amendment (2026-10-17)

**The pin moves with a replaced lock** (adr-0016, amendment of 2026-10-17). When the episode's video lock is replaced
because its service was deleted, disabled or retyped, the first generation on the new service without an explicit model
keeps the pinned model if the new service lists it, else pins the new service's first model, in the same transaction
as before. An explicit model still leaves the pin alone.
