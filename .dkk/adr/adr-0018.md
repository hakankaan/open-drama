# ADR-0018 — Character reference views

## Context

Until now a character had one reference image, a turnaround sheet: a portrait beside the full figure from the front, the side and the back. The official Seedance 2.0 prompt guide warns that such multi-view sheets cause identity drift and duplicated people, and recommends a separate close-up and full-body image. Rechecking the other video models Open Drama drives showed that the warning is not universal: the Seedance 2.5 guides rank separate images above a sheet but still accept sheets for up to five subjects and use side and back views, Wan 2.7 documents multi-view references with one character per image, Veo 3.1 takes at most three reference images, and the rest (Wan 3.0, Happy Horse, MiniMax and others) document nothing either way. So the right images depend on the target model, and a creator cannot see which ones a call sends. Sheets also shrink the face: references are sent at most 768 px wide, and every further view in one image costs the face pixels. This refines `adr-0017`'s slot rule, which sent one image per bound asset.

## Decision

- **A character holds views**: `headshot`, `body`, `side`, `back` and `sheet` (`characters.headshot_path`, `body_path`, `side_path`, `back_path`; the old `image_path` becomes the sheet). Migration 0008 keeps every existing image as the character's sheet and marks its final prompt stale, since that prompt described a sheet. The **cover** (`coverViewOf`: headshot, else body, sheet, side, back) stands for the character wherever one image is shown or sent.
- **Views are generated as a chain.** `RequestCharacterImage.views` (default headshot and full body) runs the headshot first, then each other view drawn from the headshot as its reference image. The headshot is a 1:1 close-up of the head only; body, side and back are 9:16 full figures. A character without a headshot draws it from its sheet, keeping the face; a new headshot of a character that has one starts afresh. The rest of the chain is kept on the task (`params.then`) and submitted when a view completes, in the same service and model. A view that needs a reference fails before anything is paid when the image model takes none, instead of drawing someone else. Any other view without a headshot is refused (412).
- **One final prompt describes the person**; the code adds each view's framing, background and light after the drama's style. The character-prompt skill (template v9) and the local fallback write no layout or view words.
- **Views are uploaded and removed one by one** (`UpdateCharacter.views`, a partial patch; `null` removes). A character has no `imagePath` field any more. Views cannot change while one of the character's images is generating (409), so a chain never draws its next view from a headshot other than the one it started with, and a result never overwrites an upload made meanwhile.
- **Each video model has a reference policy** (`referencePolicyFor`, matched by model family and version, so Ark, BytePlus, Bailian and ModelRunner ids agree): `sheets`, the model reads a multi-view sheet as one person; `turnaround`, the model uses separate side and back views. Seedance 2.5 has both, Wan 2.7 has `sheets`, every other model neither, from the Seedance 2.0 warning, until a comparison run says otherwise. A model's image limit (Veo's three) is applied on its own.
- **One planner chooses the images** (`planReferences` in contracts, run by `RequestShotVideo` and by the studio to preview it). Assets are chosen as in `adr-0017`: those the prompt mentions first, at most four characters and five assets, within the model's image limit, deduplicated by path. Each chosen asset sends its cover. The slots left after the shot's uploaded and the request's extra images (one that is already a chosen asset's image takes no second slot) go, in the same order, to each character's full body; where none is left and the model reads sheets, the character's headshot and body are composed into one sheet in code (768 px tiles side by side, stored like any image and named in the task's parameters). A turnaround model then gets side views, and back views last. A character's images stay together in the binding order.
- **The prompt names what each slot shows**: the legend labels each character slot (`Mei (@Image1) face close-up, Mei (@Image2) full body`; a sheet is "one person in several views"), and a provider without slot tokens gets `Reference images in order: 1 Mei (face close-up); 2 Mei (full body); 3 the location Night market.` After the legend come a headcount sentence in positive words (`Mei and Jun are 2 different people, each appearing once, never duplicated.`), since several images of one person can come out as twins and most of these models take no negative prompt, and a `Wardrobe:` line from each sent character's styling, at most 160 characters each.
- **The studio shows what is sent and warns only where the creator can act.** The character dialog shows the views with upload, remove and "draw from headshot" per view, and one button that redraws all of them; cards list the views a character has. The shot editor previews what the target model will be sent, and what is left out. Each version records what each character was sent as (`ShotVideo.sentViews`). The video stage warns when a bound character has only a sheet and the model does not read sheets, and offers to generate a headshot and full body; on a turnaround model it notes missing side and back views and offers to generate them, dismissable per episode.

## Alternatives Considered

- **Keep one sheet per character.** Rejected: the Seedance 2.0 guide warns against it, and a sheet costs the face its resolution.
- **Separate views everywhere, no per-model policy.** Rejected: Seedance 2.5 and Wan 2.7 document multi-view references, and a composed sheet is how a character's two images fit when slots run out.
- **Have the image model draw a sheet from the views.** Rejected: one more paid image that can drift from the headshot; composing in code is free and exact.
- **Policy as a provider capability flag.** Rejected: it describes how a model family reads images, the same across the providers that serve it, not what a provider's API accepts.
- **Warn on every mismatch between a character's images and the model.** Rejected: a warning nobody can act on is noise; only missing images that a click produces are worth one.
- **A per-episode outfit view** (plan 06). Deferred: it needs episode-level wardrobe data and doubles the images per character.

## Consequences

- Contracts: `CharacterView`, `GeneratedView`, `CharacterViews`, `CharacterCard.views`, `RequestAssetImage.views`, `UpdateCharacter.views` (its `imagePath` removed), `ShotAssetRef.views`, `ShotVideo.sentViews`, and `references.ts` (`MENTION`, `SentView`, `referencePolicyFor`, `planReferences`, `planShotReferences`, `imageLimitOf`), shared by the API and the studio. Migration 0008, template v9.
- A character's images cost two generations by default and four with side and back; existing characters keep working from their sheet until the studio's suggestion redraws them.
- The policies of models other than Seedance 2.0, Seedance 2.5 and Wan 2.7 are a guess until a paid comparison run settles them.
- The next view of a chain is submitted after the completed view is written; a restart between the two loses the rest of the chain. The studio shows the missing views, and one click requests them again.
