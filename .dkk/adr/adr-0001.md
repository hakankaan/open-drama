# ADR-0001 — Product scope and original work

## Context

Open Drama is a self-hostable AI short-drama studio. Its scope has to be fixed before the architecture is chosen. The project also needs one rule for where its code and texts come from, so that its licence (`adr-0012`) can be applied to every file without exceptions.

## Decision

- **Scope.** A four-stage production pipeline (script → assets → storyboard/videos → export), driven by four agents (script rewriter, extractor, storyboard breaker, prompt generator), with drama-wide characters, scenes and props, one generation lifecycle for every image and video, and FFmpeg compositing of the finished episode.
- **Original work.** All source code, CSS, prompt text, skill text, style-preset text, UI copy, icons and screenshots in this repository are written for Open Drama. Third-party material enters only as a declared dependency (npm packages, fonts, icon sets) under a licence compatible with `adr-0012`.
- Behaviour is specified first in this repository's domain model (`.dkk/domain`) and plans (`docs/plans`), and implementation works from those documents.
- Brand, product names, default ports, storage paths and default languages are Open Drama's own. Descriptive identifiers (agent type names such as `extractor`, tool ids such as `save_script`, generic environment variables such as `PUBLIC_BASE_URL` or `FFMPEG_BIN`) follow common naming; Open Drama-specific settings use the `OPEN_DRAMA_` prefix.

## Alternatives Considered

- **Accept third-party snippets with per-file attribution.** Rejected: every such file becomes a licensing review item, and prompts and skills must follow the domain vocabulary (`@[Name]`, `[Shot N]`) anyway.

## Consequences

- Prompts and skills are written from this repository's domain glossary and aggregate invariants, with their own outline.
- Contributors state that their contributions are their own original work (`CONTRIBUTING.md`, before the first release).
