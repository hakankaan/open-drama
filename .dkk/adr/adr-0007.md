# ADR-0007 — API contract: camelCase JSON validated by shared zod schemas

## Context

A snake_case wire format would force the TypeScript frontend to map case by hand in many places. Open Drama has two TypeScript apps in one repository, so one set of types can serve both ends.

## Decision

- REST under `/api/v1`, **camelCase JSON** in both directions.
- Success envelope `{ "data": … }` (201 for creates); error envelope `{ "error": { "code", "message", "details"? } }` with a matching HTTP status. Error codes: `VALIDATION_FAILED`, `NOT_FOUND`, `CONFLICT`, `PRECONDITION_FAILED`, `PROVIDER_ERROR`, `INTERNAL`.
- Every request body, query and response is described by a **zod schema in `packages/contracts`**; the API validates with them and the web client parses with them, so the types are shared by construction.
- Partial updates use `PATCH`; ids are integers; media paths are relative (`static/…`) and the client prefixes `/`.
- One enum table in `packages/contracts/common.ts` is the vocabulary for the whole system and the domain model uses the same words: `ServiceType = text | image | video`; `Resolution = 480p | 720p | 1080p`; `AspectRatio = 16:9 | 9:16 | 1:1 | adaptive`; `DramaStatus = EpisodeStatus = draft | active | completed`; `TaskStatus = FilmStatus = processing | completed | failed`; `JobStatus = running | done | failed`; `JobKind = rewrite | extraction | breakdown | videoPromptBatch`; `ExtractionTarget = characters | scenes | props`; `AgentType = script_rewriter | extractor | storyboard_breaker | prompt_generator`; `ContentLanguage = en | zh | ja | ko`. Durations are always `durationSeconds`.

## Alternatives Considered

- **OpenAPI-first with code generation.** More tooling for the same guarantee; zod schemas can emit OpenAPI later if a public API is wanted.
- **tRPC.** Ties the API to the TypeScript client; the API should stay callable with curl and from other clients.

## Consequences

- No case mapping anywhere; renaming a field is a compile error on both sides.
- The contract package becomes the reviewed surface of the system; the domain model names are used for schema names.
