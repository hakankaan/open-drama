# ADR-0009 — Local immutable media storage with derived renditions

## Context

Provider result URLs expire, reference images must be re-sent to providers, and lists must not load full-size originals. So every result must be stored locally, with thumbnails and poster frames for lists.

## Decision

- A **local media store** under `$DATA_DIR/static/{uploads,images,videos,merged,temp}`; files are uuid-named with the original extension and never rewritten, so `Cache-Control: public, max-age=31536000, immutable` is safe.
- Every generation result is **persisted locally before the task is marked completed**; the provider URL is recorded for reference only.
- **Renditions** are derived next to the original by naming convention: `_thumb.webp` (400 px) for images, `_poster.jpg` (640 px at 0.5 s) for videos and films. Derivation never blocks or fails the main operation.
- Uploads are validated by extension and MIME with per-kind size limits.
- Reference material is normalised before dispatch: images become compressed data URLs; videos/audio become public URLs through `PUBLIC_BASE_URL` or fail with an actionable message.

## Alternatives Considered

- **Object storage (S3-compatible).** Deferred; the store module has a small surface (`store`, `toAbsolute`, `deriveRenditions`) so a backend can be swapped. Not needed for a single host.
- **Serving media through Next.js image optimisation.** Rejected: originals are large and already sized; renditions are cheaper and deterministic.

## Consequences

- Backups and migrations are directory copies.
- Disk usage grows with generation; the storage card reports usage by bucket, and a cleanup command for orphaned files is a later addition.

## Amendment (2026-09-29)

**Unused files are removed from the storage settings.** The Storage tab lists the stored files nothing refers to any more (`GET /storage/orphans`) and deletes them after a confirmation (`DELETE /storage/orphans`, which works the list out again on the server). A file counts as unused only when all of these hold:

- it sits in `uploads`, `images`, `videos` or `merged` (never `temp`) under a name the store wrote: a uuid, or a uuid's `_thumb`/`_poster` rendition, which follows its original;
- it was last written more than 24 hours ago, which covers a result stored before its task row and an upload not yet attached;
- its uuid appears nowhere in the database. Every column of every table is read, not a list of path columns, so a column added later cannot make a file look unused.

Soft-deleted dramas, episodes and assets still mention their files, so those files are kept; purging deleted projects is a separate, later decision. Provider result downloads now go through the same guarded fetch as remote reference images, trusting only the service's own configured host.
