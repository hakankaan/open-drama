# ADR-0006 — Agents run on the AI SDK tool loop with file-based prompts and skills

## Context

Four agents (script rewriter, extractor, storyboard breaker, prompt generator) run tool-calling loops against a configurable text model. A full agent framework would provide agents, workspaces and skills, but what we need from it is small (a tool loop, a filesystem jail, skill discovery) relative to its dependency weight, and such frameworks' API surfaces change often.

## Decision

Implement agents directly on the **Vercel AI SDK** text-generation tool loop (`generateText` with tools and a step limit), wrapped in a thin `runtime/` layer so agent code never imports the SDK directly. Instructions are assembled from **files in a writable workspace** (prompt file per agent with language variants, `SKILL.md` documents discovered under per-agent prefixes) plus a language directive. Text-provider quirks (thinking off on relays, temperature, output limits) are applied as `fetch` wrappers. Agent user messages are English templates owned by the API.

## Alternatives Considered

- **An agent framework.** Rejected: extra framework and version churn for features we build in ~200 lines; a path-confined file module gives the workspace jail.
- **LangGraph / custom state machines.** Not needed: each agent is a single loop with a fixed tool set.
- **Prompts in the database.** Rejected: files are diffable, editable by hand, and shippable as a template; the UI edits them through jailed file endpoints.

## Consequences

- Fewer dependencies; the SDK is pinned and isolated.
- Success of a run is judged by persisted side effects, so every agent's caller checks its target field after the run (and retries once with a "call the tool" reminder).
- The workspace template is copied once into the data directory; edits survive upgrades, and newer templates only add missing files.

## Amendment (2026-10-11)

**The workspace gains an assistant folder** (`adr-0016`, template v7). `workspace/assistant/instructions.md` and `workspace/assistant/<name>/SKILL.md` are written for the creator's AI assistant, not for a production agent: the endpoint serves them as its instructions, prompts and resources, with the language-variant convention of the prompt files. They are never injected into an agent's instructions, are not listed by the skills endpoints, and are copied once like the rest of the template; a document whose frontmatter fails validation is skipped and named by `get_status`.

## Amendment (2026-10-14)

**Unedited workspace files follow the template** (`adr-0017`, template v8). `workspace/.template-history.json` holds the sha-256 of every version each template file has had. At boot a missing file is copied, a file whose content is a past template version is replaced by the current one, and any other file counts as the creator's edit: it is kept and reported in the boot log. The copy-once consequence above now holds only for edited files.

## Amendment (2026-10-18)

**Agents that write something new think first.** Each agent definition says whether its runs think: the story writer, episode planner, episode writer, script rewriter, asset designer, storyboard breaker and prompt generator do; the extractor and the recap writer, which only restate what they read, do not, and neither do shot checks. On relays the `fetch` wrapper asks for thinking on a thinking run (ModelRunner `reasoning_effort: "high"`, Ark and other OpenAI-style relays `thinking: {type: "enabled"}`, Gemini `thinkingLevel: "high"` on 3.x and a dynamic budget on 2.x) and still turns it off on the others unless `OPEN_DRAMA_AI_DISABLE_THINKING=0`. `OPEN_DRAMA_AI_THINKING_ON_PATCH` replaces the thinking-on keys as `OPEN_DRAMA_AI_THINKING_OFF_PATCH` replaces the thinking-off ones. Official OpenAI and Gemini hosts keep the model's own default, as before.

**The tool loop streams** (`streamText`, not `generateText`), so a long thinking step stays within a relay's limit on unstreamed requests (ModelRunner ends them at 95 s). Results and failures are the same as before: the first stream error is rethrown, the step timeout and a cancel still end the run. The reasoning the provider streams back is sent with the next step of the loop, which thinking models that call tools require. Thinking tokens, when reported, are logged with the run.
