# ADR-0003 — Hono on the Node adapter as the HTTP framework

## Context

The API needs routing, middleware, multipart uploads, static file serving with range requests, and zod validation, on Node.js. Hono on `@hono/node-server` keeps handlers small and portable.

## Decision

Use **Hono** with the Node adapter (`@hono/node-server`), `@hono/zod-validator` bound to the contract schemas, `serveStatic` for `/static`, and a single error handler producing the envelope from `adr-0007`. Handlers stay thin: parse → validate → call a service function → envelope.

## Alternatives Considered

- **Fastify.** Excellent and Node-native with schema validation built in; slightly more ceremony for the same result. Acceptable fallback if Hono's Node adapter proves limiting for streaming or range requests.
- **Express.** Ubiquitous but dated typing and middleware ergonomics.
- **NestJS.** Too much structure for a single-user tool.

## Consequences

- Very small HTTP layer; most code lives in per-context service modules that do not import Hono at all, which keeps the framework replaceable.
- Range-request behaviour of `serveStatic` must be verified for large video files early (Plan 1 Phase 3); otherwise a small custom handler serves `/static`.
