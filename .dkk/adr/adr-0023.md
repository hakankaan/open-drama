# ADR-0023 — Per-episode outfits

## Context

Plan 06 item 1 deferred the outfit view (adr-0018). A character's styling and its full-body, side and back views are
the same in every episode, so a story where someone changes clothes between episodes (a uniform at work, a coat in the
rain, a wedding) has two bad options: edit the character and break every earlier episode's next regeneration, or keep
the old clothes in the references and fight them in each prompt. The references win that fight on most models, and the
shot check (adr-0022) then flags the deliberate change as an outfit error.

## Decision

- **The outfit lives on the episode link** (`episode_characters.outfit`, text, empty by default, and
  `episode_characters.outfit_path`, migration 0014). An empty outfit means the character wears its own styling and
  views, as before.
- **SetEpisodeOutfit** (`PATCH /characters/:id/outfit`, `{ episodeId, outfit?, outfitPath? }`) sets the text and the
  picture of a live character linked to a live episode of its drama (404 otherwise). A changed outfit drops the
  picture, which shows the old one, unless the same request gives one; an empty outfit keeps no picture. A picture
  needs an outfit (412) and a stored file (400), and cannot be given or removed while one is being drawn (409), since
  the drawing would land over it.
- **RequestOutfitImage** (`POST /characters/:id/outfit/image`) draws the full body in the outfit from the character's
  headshot, 9:16, in the episode's locked image service (claimed on first use, adr-0016), with a prompt made in code
  from the full-body framing, the character's appearance and the outfit, prefixed with the drama's style; no agent
  runs. It is refused without an outfit or a headshot (412) and while the character has any image generating (409,
  the same one-image slot as its views); on an image model that takes no reference image the task fails before
  anything is paid. The task is the
  character's, marked `params.outfit = { episodeId, outfit }`; it lands on the link only while that episode is live
  and the outfit is still the text it was drawn for, so an edited outfit never receives a picture of the old one.
  Outfit tasks are kept out of the character's own latest-image state and out of other episodes' task lists, but
  they do hold the character's views read-only while they run (adr-0018), since they are drawn from the headshot.
- **Where an outfit is set, the episode's shots use it.** The character's views in that episode become: the headshot,
  the outfit picture as the full body, no side or back view (they show the old clothes), and the sheet only while it is
  the only picture of the face (identity before clothing). The video prompt's wardrobe line and the keyframe prompt
  take the outfit instead of the styling, and with an outfit but no picture the identity sentence asks for the face and
  hair of the references and the clothes described, so the headshot alone does not pull the old outfit back. The shot
  check compares the outfit point with the outfit picture, says the reference shows this episode's outfit, and gives
  the model the wardrobe line. The storyboard agent's context lists each character's outfit, for the episode and for one shot.
- **A changed outfit or outfit picture marks the keyframes of that episode's shots with the character stale**
  (adr-0019); other episodes are untouched.
- **Studio.** The character dialog on an episode's assets stage has an "Outfit in this episode" field (saved when it
  loses focus) with the picture beside it: draw, redraw, upload, replace and remove. The shot editor previews the
  references with the outfit applied, and the advice to generate side and back views skips characters with an outfit.

## Alternatives Considered

- **An outfit as a character view** (plan 06's `RequestAssetImage.view: outfit`). Rejected: views belong to the
  character in every episode; an outfit is true of one episode, so it lives where the character meets the episode.
- **A wardrobe library (named outfits reused across episodes).** Deferred: one text per episode covers the case, and a
  repeated outfit can be pasted. A library adds naming, sharing and deletion rules before anyone needs them.
- **Keep the side and back views beside the outfit picture.** Rejected: they show the old clothes, and on turnaround
  models three images outvote one.
- **Draw the outfit from the full body instead of the headshot.** Rejected: the full body carries the old clothes into
  the new picture; the headshot carries only the face and hair.

## Consequences

- Contracts: `EpisodeCharacterCard` (`outfit`, `outfitPath`, `latestOutfitTask`), `UpdateEpisodeOutfit`,
  `RequestOutfitImage`, `ShotAssetRef.outfit`, and `outfitViews` (shared by the API and the studio). Migration 0014
  also carries adr-0019's keyframe revisions.
- An outfit picture costs one image per character per episode; without one, the shots send only the face, and the
  clothes rest on the prompt.
- Assistant (MCP) tools for outfits are not there yet; the parity inventory lists them for iteration 2.
