## Later (no iteration assigned)

- Multi-user authentication (`ownerId` on dramas and model services) — Plan 1 §9.
- Purge deleted projects: dramas, episodes and assets are soft-deleted and nothing restores them, but their rows (with their shots, tasks and films) keep their files referenced, so the unused-files cleanup (`adr-0009` amendment) cannot reclaim them. A purge would hard-delete soft-deleted rows, after a confirmation or a retention period, and the cleanup then frees their files.
- Generations cut off mid-submission: a restart before the provider's answer fails the task (its error says it may still have run and been billed), and a retry can pay twice. Sending an idempotency key where a provider takes one, or keeping such a task in an "unconfirmed" state that asks before a retry, would close it — `adr-0005` amendment (2026-10-09).
- Aggregate reference-duration limits (total seconds of reference video/audio per request) for MiniMax, Seedance 2.x and Wan: probe uploaded media, keep the duration, validate before a task is claimed.
- Seedance mention token: the adapter writes `Name (@ImageN)`. The BytePlus English guides use `@Image 1`, `@Image1` and `[Image 1]` (capital `Image`, counted per asset type); the Volcengine Chinese docs use `图片1` / `@图片1`. Keyed calls on 2026-09-29 accepted it: BytePlus Seedance 2.0 with one reference, and ModelRunner Seedance 2.0 with two (`Flooded greenhouse (@Image1)`, `Pip (@Image2)`), where the clip followed both. Still open: whether Volcengine (or Chinese-language prompts) should render `图片N`.
- ModelRunner families not yet run live (`adr-0013` amendment 5): request bodies validate against each endpoint's schema. Seedream, Seedance, Veo 3.1 and Happy Horse 1.1 have run with real keys; Kling, Pixverse, Hailuo, Wan and GPT Image have not, so whether they take references as data URLs is unconfirmed. Also open:
  - Happy Horse wants references at least 400 px on the short side, but references are scaled to fit 768 px, so a very wide reference could fall short;
  - Hailuo takes no shape input, so its clips' shape is not checked;
  - Veo's reference mode takes no length: it renders 8 s (confirmed 2026-10-05) whatever the shot asks for, and the task's recorded `durationSeconds` is the requested length, not the rendered one;
  - Happy Horse's endpoints have no audio flag; its clips come with sound.
- ModelRunner catalog picker lists endpoints the adapter refuses (LongCat needs a start frame): checking a model when it is added in Settings, through the same schema read, would catch it before a shot request does.
- Seedance 2.5 on Ark: the model's `duration: -1` (model picks the length) is not offered.
- Drag-and-drop shot reordering, workbench keyboard shortcuts — Plan 3 "Later".
- Rolling series summary for very long series: the `series` block (`adr-0014`, `adr-0015`) carries the outline whole and every earlier episode's recap, dropping the oldest recaps beyond 60k characters; a maintained whole-series summary would keep the early episodes present at a fixed cost.
- Re-plan the unplanned episodes (`adr-0015`): the planner is append-only, so after an outline change the creator deletes the planned-but-unwritten episodes by hand before planning again; a "replace the unplanned episodes" option would delete them (never a written one) inside the same plan job.
- Seed the cast from the outline (`adr-0015`): the outline names the recurring characters before any episode exists, but characters are only extracted from a script; a drama-scoped extraction from the outline would let their reference images be generated before episode 1.
- Suggested episode count in the plan dialog (`adr-0015`): the outline's season shape names a count that the creator copies into the dialog by hand; parsing it, or having the story writer return it, would prefill the field.
- Workspace files a creator edited are kept on a template upgrade and only named in the boot log (`adr-0017`); the studio could list them with a diff against the current template, so a creator can take a fix by hand. Unedited files now follow the template, which settles the duplicated rewriter layout rules of pre-v6 workspaces.
- `adr-0017` request fields not yet run live: the seed on Ark Seedance and Wan, Wan's `negative_prompt` and `prompt_extend: false`, and ModelRunner's `seed`, `negative_prompt` and `prompt_optimizer` roles. The bodies were checked against a local mock and the public endpoint schemas only; whether a retake on the same seed reproduces a clip is unmeasured.
- Video model pin after the locked service goes (`adr-0017`): an episode whose locked video service was deleted or disabled keeps the dead id, so requests fall back to the highest-priority service, unpinned, on its first model, and the stored pin is never moved. Re-locking to the fallback (or asking the creator) would restore the pin; the stale lock itself predates the pin (`adr-0016`).
- Reference policies of untested video models (`adr-0018`): Seedance 2.0's guide warns against multi-view sheets, the Seedance 2.5 and Wan 2.7 docs describe multi-view references, and every other model (Veo 3.1, Wan 3.0, Happy Horse, MiniMax, Kling, Pixverse, Vidu) is treated like Seedance 2.0 by assumption. A paid comparison run per model (one character as a sheet, as headshot + body, and as headshot + body + side + back, same prompt and seed) would settle `referencePolicyFor`.
- Character view chain after a restart (`adr-0018`): the next view is submitted after the completed one is written, so a crash between the two drops the rest of the chain. Keeping the pending views on the character, or resuming them from completed tasks whose `params.then` has no follow-up task, would close the gap; today the studio shows the missing views and one click requests them.
- Orphan clean-up during generation: the media clean-up (Settings › Storage) keeps every file a database row or task names, but a task holds its reference images only in memory until it sends them. An image detached from its asset while a video or image task is queued, and swept in that window, fails the task. Recording every local input path in the task's params before dispatch would close it (`adr-0018` made a character's views read-only while its own image task runs; video tasks are not covered).
- Per-episode outfits (plan 06 item 1's `outfit` view and `episode_characters.outfit`): left out of `adr-0018`. The wardrobe line in the video prompt comes from the character's styling, the same in every episode.
- Path deduplication with views (`adr-0018`): slots are deduplicated by path, so a character view that reuses another asset's image (an upload picked twice) is silently not sent for the second one. The studio's preview shows it, but nothing says why.
- Template files removed from the workspace template stay in a creator's workspace after an upgrade (`adr-0017`): the upgrade adds and replaces, never deletes. A tombstone list in `workspace/.template-history.json` would let it remove an unedited file the template dropped. A missing history only keeps more files; a malformed one fails the boot.
- ModelRunner seed bounds (`adr-0017`): the seed is written as the endpoint's `seed` field without its schema `minimum`/`maximum`; seeds stay in [0, 2147483647], the range the checked Wan v3.0 and v2.7 schemas declare, so a narrower endpoint would refuse the request. Likewise a prompt-expansion switch is sent `false` even if a schema fixed it with `const: true`.
- Reference slots dedupe by image path (`adr-0017`): two bound assets sharing one image file take one slot under the first one's name; the second gets no `@Image N`, and is neither sent nor listed in `droppedReferences`.
- Seedance 2.0 on ModelRunner refused its own generated soundtrack once (`OutputAudioSensitiveContentDetected.PolicyViolation`, 2026-10-06, four minutes in): the task failed cleanly, and the same request with `generateAudio: false` completed. The video panel could offer that retry when the error carries this code.
- End frames (`adr-0019`): ModelRunner's first/last-frame endpoints take an end picture (`end_image`, `end_image_url`, `last_frame_url`) and Ark a `last_frame` role, but no shot has an end picture to send yet. `RequestShotVideo.endFrameUrl` and a second keyframe per shot would add it, most usefully with chaining.
- Ark's first frame (`adr-0019`): the content item with `role: "first_frame"` comes from third-party Seedance guides, not the official ModelArk reference, and has not been run live. If Ark refuses it, its `firstFrame` cap goes back to false and keyframes there become previews and colour targets only.
- Keyframe cast after rebinding (`adr-0019`): a keyframe is not marked stale when the shot's bindings, framing or prompt change after it was drawn, so a video can start from a picture of the old cast. A stale flag like the video prompt's would catch it.
- Continuing shots after a restart (`adr-0020`): a shot waiting for the video of the shot it continues waits in process, so a restart fails it and it is requested again. A dependency recorded on the task and redispatched at boot would keep it.
- Stale continuations (`adr-0020`): regenerating a shot leaves the shot that continued its old version joined to nothing; the merge then cuts between them and nothing in the studio says the continuation is stale. Comparing `chainedFrom.videoPath` with the previous shot's current video would flag it, and offer to regenerate.
- Ambience under lip-synced shots (`adr-0021`): a pinned spoken shot is made silent, so the film plays only its line there. Generating the video's own sound as well and laying it under the line (ducked), or a separate ambience track per scene, would bring the room back.
- Narrator voice-over (`adr-0021`): only a bound, on-screen character speaks; a narrator's line over the picture (no lip sync) would be a second audio track per shot or episode.
- Line audio and lip sync from an assistant (`adr-0021`): the MCP tools neither request line audio nor lip syncs, nor set a character's voice; an assistant can write lines through the shot tools only.
- Speech and lip-sync model pickers (`adr-0021`): each request uses the highest-priority active service and its first model; the studio could offer a model per drama like the video pin.
- Shot checks from an assistant (`adr-0022`): no MCP tool requests a check or reads its result yet, beyond what the shot tools return.
- Face-identity metrics for shot checks (`adr-0022`): an embedding comparison (ArcFace-style face recognition, DINO similarity) would score identity, which the vision model is told not to judge. It needs a local model runtime, and the common pretrained face models are licensed for non-commercial research only.
- Regenerating flagged shots (`adr-0022`): the check is a signal only; an opt-in "regenerate flagged shots" (with a cap on attempts) could follow once checks prove reliable.
- Vision defaults for Ark and BytePlus (`adr-0022`): their presets suggest no vision model, so a creator types one in; the quick setups for those platforms write no vision service.
- Shot checks on live models (`adr-0022`): checks have only run on the stub. How `deepseek/v4.1-flash`, `gpt-5` and `gemini-2.5-flash` judge the sheets, how often they flag in error, and whether they keep to the JSON answer, is unmeasured.
- Pinned voices on live models (`adr-0021`): speech and lip sync have only run on the stub. Whether ElevenLabs and Chatterbox accept the sample as a URL or data URI, how LatentSync and sync v2 treat the lead-in and the silence after the line, and whether their output keeps the source's frame rate, is unmeasured.
- Chaining on live models (`adr-0020`): the take has only run on the stub. Whether Seedance, Veo, Kling and Wan start exactly on the given frame (rather than near it), and how much identity drifts over two continued shots, is unmeasured.
