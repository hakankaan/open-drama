## Data model

Migration 0007 (done) adds only `episodes.video_model`. The rest below belongs to the open items and goes into later migrations.

- `characters`: `headshot_path`, `body_path`, `side_path`, `back_path` (done, migration 0008; `image_path` now holds the multi-view sheet), `voice` (text, default ''), `voice_sample_path`.
- `episode_characters`: `outfit` (text, default ''), `outfit_image_path` (this episode's full body; overrides the character's). Deferred (BACKLOG).
- `shots`: `speaker_id`, `line` (one speaker per shot), `line_audio_path`, `line_audio_seconds`, `keyframe_first` (bool), `keyframe_path`, `continues_previous` (bool), `qa` (json, carries the video path it judged). The unused `image_prompt` column becomes the keyframe prompt.

- `episodes`: `video_model` (done: the model pin, claimed by the first generation on the locked service without an explicit model; moves to the service's first model, written back, when the service no longer lists it).
- `UPDATE characters SET final_prompt_stale = 1 WHERE final_prompt IS NOT NULL` (done, migration 0008: sheet prompts become person descriptions).

## Items

1. **Headshot + full body.** — *implemented as views with a per-model policy (`adr-0018`), no outfit view.* A character holds `headshot`, `body`, `side`, `back` and `sheet` (the old image). `RequestAssetImage.views` (default headshot and body) runs a chain: the 1:1 head-only headshot first (drawn from the sheet while the character has no headshot), then each 9:16 view drawn from it, the rest of the chain kept on the task as `params.then`. One final prompt describes the person; code adds each view's framing (character-prompt skill and fallback rewritten, template v9). `referencePolicyFor(model)` says whether a model reads a multi-view sheet as one person (`sheets`: Seedance 2.5, Wan 2.7) and whether it uses side and back views (`turnaround`: Seedance 2.5); every other model gets neither. `planReferences` (contracts, shared by API and studio) sends each chosen asset's cover, then bodies while slots remain, a sheet composed in code from headshot and body when none remain and the model reads sheets, then side views and back views on a turnaround model. The legend labels each slot's view, providers without slot tokens get an ordered list, and the prompt gains a headcount sentence and a wardrobe line. The studio previews the plan per shot, records `sentViews` per version, and warns only where a click helps (sheet-only characters on a model without `sheets`, missing side/back on a turnaround model). Planned design, for the record: `RequestAssetImage.view: headshot | body | outfit` (characters); outfit = appearance + `episode_characters.outfit` with the headshot as reference; image tasks carry `params.view` (+ `episodeId` for outfit); `PATCH /episodes/:id/characters/:characterId/outfit`. The outfit part is deferred (BACKLOG).
2. **Prompt discipline, in code** — *implemented as below until headshots exist (item 1): slots are bound characters (at most 4) → scene → props, at most 5 bound assets, the ones the prompt mentions chosen first; the identity sentence covers face, hair and outfit; the language sentence is added only when the prompt holds dialogue; the storyboard skill caps four characters per shot but `speaker`/`line`/`keyframeFirst`/`continuesPrevious` wait for items 5 to 7. The studio greys out a version's dropped references.* Planned design (`storyboard/video.ts`): slot priority and order = headshots (at most 4 characters) → scene → bodies/outfits → props, bound assets capped at 5 slots, uploads and extras after within `caps.images`; dropped ones reported. Legend line naming each slot (skipped for plain-mention providers); mentions render with the headshot slot. `0-3s:` lines rewritten to `Shot N:`. Scene `lighting` appended verbatim. Constraint sentence keeping faces, hair and outfits; spoken-language sentence. Prompt expansion off (`aliyun prompt_extend: false`; ModelRunner `enable_prompt_expansion`/`prompt_extend`/`prompt_optimizer` set false). Video-prompt and storyboard skills rewritten (untimed `Shot N`, `@[Name]` on every mention, one camera move per sub-shot, single-speaker shots, `speaker`/`line`/`keyframeFirst`/`continuesPrevious` fields).
3. **Seed + negative prompt.** — *implemented with one difference: caps gained only `seed`. The negative prompt is a constant on every adapter record, sent where the model's API takes one (Wan, ModelRunner `negative_prompt`), so it needs no cap; `firstFrame`, `endFrame` and `firstFrameReferences` arrive with item 6. A seed for a model without one is refused; the retake is offered only while the version's model is the current target and reuses the seed with the current prompt and references.* Planned design: `RequestShotVideo.seed`; a random seed is drawn when the model takes one and recorded in task params; `ShotVideo` shows seed and model (retake with the same seed). Fixed negative prompt (extra people, twins, identity change, text, watermark) where the model takes one. Caps gain `seed`, `negativePrompt`, `firstFrame`, `endFrame`, `firstFrameReferences` (table for Ark/MiniMax/Aliyun, schema for ModelRunner, all true for the stub).
4. **Post v1** — *implemented (`adr-0019`) with one difference: the colour target is the keyframe the clip started from, else the shot's keyframe; the scene plate is not used, and a clip without a keyframe is not graded. The encoder line says how many clips were matched.* Planned design (`compositing/render.ts`): conform to a fixed frame from drama aspect + episode resolution at 24 fps (adaptive keeps the first clip's frame); damped mean/std colour match per clip to the shot keyframe, else the scene plate (never the previous clip), via `lutrgb`; series look on the drama (none, warm, cool, teal_orange, faded, mono) as built-in filters after concat; two-pass `loudnorm` (I -16, TP -1.5, LRA 11) + `aresample=48000` in a remux pass. `MergeShots.colorMatch` (default true); the encoder string records the options.
5. **Pinned voices.** — *implemented (`adr-0021`) with these differences: a speech or lip-sync request uses the highest-priority active service (no picker, no lock); the speech model's named voices come from its schema and a model with a clone field clones the sample; the shot grows to hold a 0.5 s tail as well; a pinned video is refused before anything is paid when the line does not fit the model's longest video or no lip-sync service exists; the result's picture is kept with the padded line muxed over it; a lip sync starts from the original video, never a synced copy, and becomes current only while the shot still plays the video it was asked for with the same line audio; the automatic sync refuses a line re-spoken meanwhile (a failed task says why) and a manual one a line longer than the video. MCP tools for line audio and lip sync wait for iteration 2.* Planned design: New service types `speech` and `lipsync` (ModelRunner + stub; optional, so readiness only counts text/image/video; MCP `BLOCKS`, catalog query, probe, quick-setup defaults `elevenlabs/tts/multilingual-v2` and `bytedance/latentsync`, settings cards). New generation types `speech` and `lipsync`, both shot-owned. `POST /shots/:id/line-audio` (TTS with the speaker's voice or voice sample, content language); completion grows the shot to fit the line (never shrinks). With `dramas.pinned_voices`, a shot with a line needs its line audio, generates silent, and its completed video submits a lip-sync task automatically (`POST /shots/:id/lip-sync` for manual runs). The line audio is padded with a 0.5 s lead-in to the video length; inputs go as PUBLIC_BASE_URL URLs, else a fresh provider result URL, else data URIs. Lip-sync results join the shot's video history. Without pinned voices, a speaker's voice sample is sent as reference audio where the model takes audio (interim style anchor). Shots without a line get "Nobody speaks." in pinned mode. Ambience under lip-synced shots is a follow-up.
6. **Keyframes.** — *implemented (`adr-0019`) without end frames (backlog): the keyframe prompt is the shot's existing `image_prompt`; the first frame goes without reference images on every provider; ModelRunner's first-frame roles are `start_image_url`, `image_url`, `image`, `first_frame_url`, `first_frame_image`; MiniMax and Bailian take none. The keyframe sheet batches every missing keyframe rather than flagged shots.* Planned design: `POST /shots/:id/keyframe`: shot-owned image task, references = headshots, bodies/outfits, scene plate, props within the image model's limit; prompt from `image_prompt` or composed locally from the first sub-shot. Video requests use the keyframe as first frame when `caps.firstFrame` (`useKeyframe` default true, otherwise reported as not used). ModelRunner gains first-frame (`start_image_url`, `image_url`, `image`, `first_frame_url`) and end-frame roles and mode siblings `text-to-video`, `reference-to-video`, `image-to-video`, `first-last-frame(-to-video)`; Ark sends roles `first_frame`/`last_frame` without reference images. `RequestShotVideo.endFrameUrl` for first/last-frame shots. Contact-sheet grid of keyframes in the video stage with a batch for flagged shots.
7. **Chaining.** — *implemented (`adr-0020`) with these differences: the frame is taken a quarter second (6 frames) before the end of what the film shows of the clip, and the merge ends the previous clip on that frame rather than dropping a fixed 6 frames; the continuing clip starts 1 frame in and takes the previous clip's grade. A shot that cannot continue (no first-frame model, reference video or audio, a third in a row, no previous video) is refused rather than made as a cut. The wait is in process, so a restart fails waiting tasks like slot-waiting ones; the studio's batch sends a continuing shot after the request for the shot before it. The breaker and video-prompt skills know the field (template v10).* Planned design: A `continues_previous` shot takes the previous shot's frame at its play end minus 6 frames as first frame; at most 2 continuations per take (precondition beyond); the model must take a first frame. The task waits outside the episode slot for the previous shot's running video task, fails if it fails, and records `params.chainedFrom`. The previous shot's prompt gets a neutral-pose ending. The film trims 6 end frames of the previous clip and 1 start frame of the chained one.
8. **QA signal.** — *implemented (`adr-0022`) with these differences: the frames go to a new optional `vision` service type (a chat model that reads images; quick-setup default on ModelRunner `deepseek/v4.1-flash`), not the text service; there are no identity scores, the model is told not to judge faces; the rubric is people, outfit, scene and artifacts, each ok or flagged with a note in the content language, and code skips outfit without a pictured character and scene without a scene image; the frames (at 1/6, 1/2 and 5/6) and the references (each character's full body, else its cover, then the scene image) go as two contact sheets; the request is synchronous (90 s), a check is stored only while the shot plays the video it judged and hidden once it plays another; the batch checks unchecked videos or the selection, two at a time; no review queue and no automatic regenerate. MCP tool and face-embedding metrics are backlog.* Planned design: `POST /shots/:id/qa`: three frames of the current video plus headshots and scene plate go to the text service's model (vision) for a rubric (identity per character 0-5, extra people, outfit, scene, artifacts, verdict ok/check). Stored on `shots.qa`, shown as a badge, never blocks a merge. Batch check in the video stage.
